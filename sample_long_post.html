Simsoc: Dynamic State Sorting to Mitigate Warp Divergence in Multi-Agent RL

Status IN DEVELOPMENT
Tech Stack PyTorch, FLAME GPU, CUDA

When simulating complex multi-agent systems via Reinforcement Learning on GPUs, performance often degrades catastrophically due to warp divergence when agents enter different behavioral states. This architecture simulates complex agents entirely within GPU VRAM, employing dynamic Radix Sorts to ensure thread congruency.

1. The Divergence Penalty

Graphics Processing Units execute instructions in blocks of 32 threads known as warps. This SIMT (Single Instruction, Multiple Thread) paradigm is exceptionally fast provided all threads within a warp execute the exact same instruction simultaneously. However, in an agentic simulation, agents possess memory and independent states.

The Bottleneck

If Agent A decides to explore while Agent B decides to attack, the CUDA warp must process both execution branches sequentially, effectively halving throughput.

2. Mathematical Formulation

Let the set of all agents be $A = \{a_1, a_2, \dots, a_n\}$. At any timestep $t$, an agent occupies a state $S_t(a_i) \in \mathcal{S}$. In a naive array configuration, agents are stored sequentially by ID, resulting in a randomized distribution of states within a memory segment.

$$ \text{Cost}_{warp} = \sum_{j=1}^{k} C(branch_j) $$ Execution Cost of a Divergent Warp

Our objective is to minimize $k$ (the number of unique states within a single warp) so that $k \approx 1$.

3. GPU Radix Sorting implementation

To achieve $k=1$, the memory arrays must be reorganized. Before the execution of the primary neural network inference kernel, a highly optimized GPU Radix Sort reorganizes the agent arrays using their current state integer $S_t(a_i)$ as the sorting key.

Unsorted Memory (High Divergence)
Warp 1:
[State 1] [State 2] [State 1] [State 3]...
-> Instruction serialization required.
Sorted Memory (Zero Divergence)
Warp 1:
[State 1] [State 1] [State 1] [State 1]...
-> Maximum SIMT throughput.

4. Early Profiling Results

Sorting memory on a GPU takes time. The core research question was whether the time spent sorting was offset by the time saved eliminating divergence. Early profiling via Nsight Compute indicates a significant net positive.

Nsight Compute Profiler Output 
> Profiling baseline kernel (No Sort)...
Warp Issue Efficiency: 32.4%
L1 Cache Hit Rate: 54.1%
Execution Time: 8.4ms

> Profiling sorted kernel...
Warp Issue Efficiency: 96.8%
L1 Cache Hit Rate: 89.2%
Execution Time: 3.1ms (Including 0.8ms sort overhead)
[Result] 2.7x Speedup observed.

All benchmarks were conducted on an NVIDIA RTX 4090 with 24GB VRAM. It should be noted that Radix Sorting requires a secondary buffer of equal size to the original array (Out-of-Place sorting). Consequently, the maximum agent count is effectively halved compared to a standard unoptimized implementation.
